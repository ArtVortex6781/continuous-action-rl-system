# Continuous Action RL System

**Continuous Action RL System** — система для проведения воспроизводимых экспериментов по обучению агента с подкреплением (Reinforcement Learning, RL) в средах с непрерывным пространством действий.

Проект разрабатывается в рамках производственной практики и ориентирован на полный цикл RL-эксперимента: от конфигурации и обучения до сохранения политики, независимой оценки и анализа результатов. Цель — построить **целостную программную систему**, а не ограничиться реализацией TD3 в одном скрипте.

## Концепция и архитектура

Целевой сценарий работы:

```text
Configuration
    ↓
Experiment / Run
    ↓
Gymnasium Environment ↔ TD3 Agent
              ↓
           Training
              ↓
      Metrics / Checkpoints
              ↓
     Independent Evaluation
              ↓
       Tracking / Storage
              ↓
       Analysis / Comparison
```

Архитектура разделена на две основные подсистемы:

- **Локальная RL-подсистема** — конфигурация экспериментов, взаимодействие со средой, обучение агента, checkpoints, независимая evaluation и локальные результаты.
- **Tracking backend** — централизованный учёт конфигураций, запусков, метрик, статусов и результатов оценки через API и базу данных.

Обучение и оценка выполняются на локальном компьютере. VPS предназначен для tracking backend, **не для выполнения RL-обучения**. Недоступность сервера не должна останавливать локальный эксперимент.

Это **целевая архитектура MVP**, а не описание уже полностью работающих компонентов.

## Current Status

**В разработке — Этап 1: RL-ядро и эксперименты.**

Базовый архитектурный замысел согласован: определены границы системы, основные требования, ответственность компонентов, смысловые контракты и принципы организации `Experiment` / `Run`.

Сейчас архитектура последовательно уточняется по подфазам и проверяется реализацией. В частности, прорабатываются модели конфигурации, правила валидации и публичные интерфейсы Configuration.

Принятые решения могут корректироваться по результатам практической разработки. **Полный end-to-end сценарий системы пока не проверен.**

## Planned MVP

Планируемые возможности минимальной версии:

- **Собственный TD3** на Keras для сред с непрерывными действиями.
- **Конфигурируемые эксперименты** в Gymnasium с фиксируемыми параметрами и seed.
- **Training**, сбор метрик и сохранение policy checkpoints.
- **Independent Evaluation** сохранённой политики, в том числе после завершения обучения.
- **Локальное хранение результатов** и передача данных в удалённый tracking backend.
- **Анализ и сравнение запусков**, построение графиков по сохранённым данным.

Для первоначальной отладки предусмотрена `Pendulum-v1`; для более сложных экспериментов рассматривается `LunarLander-v3` с `continuous=True`.

Перечисленные возможности являются **планом разработки**, а не заявлением об их завершении.

## Technologies

**Локальная RL-часть (принятый стек):** Python 3.12, Keras 3, TensorFlow (CPU), Gymnasium, NumPy, pytest.

**Tracking backend (запланирован):** FastAPI, Uvicorn, SQLAlchemy, Alembic, PostgreSQL; развёртывание через Docker Compose и Nginx на VPS.

В текущем MVP используется TensorFlow CPU под Windows 11. GPU-backend и другие RL-алгоритмы рассматриваются как возможные последующие расширения.
